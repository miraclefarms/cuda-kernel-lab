# 跨篇接口约定（草案，第 03 篇定稿）

系列的设定是：每篇留下一个零件，最后在 capstone 里拼起来。零件能不能拼，取决于下面
四项接口在第一篇就对齐。**这四项定稿前不要批量推进 S1。**

当前状态：草案。定稿后本文件顶部改为「v1，冻结于 commit xxx」，之后改动需要同步检查
所有已有 kernel。

## 1. Tile 描述符构造

谁负责构造 TMA 描述符、描述符放在哪、多个 kernel 之间怎么复用。

待定：描述符构造是放在 host 侧工具函数里（每个 kernel 自己建），还是收进 `bench/` 的
统一封装。倾向后者，因为 04–08 篇会反复用同一组 shape。

## 2. Pipeline 深度参数化

多级缓冲的级数必须是编译期常量（影响 SMEM 分配），但系列要扫描它来画收益曲线。

待定：统一用 `template <int Stages>` 还是宏 + 显式实例化列表。倾向模板参数 +
`bench/` 侧的实例化表，这样扫描深度不需要改 kernel 代码。

## 3. Accumulator 布局

`wgmma` 的 accumulator 驻留在寄存器，布局由指令形状决定；epilogue 需要知道它。

待定：是暴露原始 fragment 布局，还是包一层 `AccumulatorView` 抽象。后者更好写 epilogue，
但会挡住「寄存器压力从哪来」这个 S2 要讲的问题。倾向暴露原始布局 + 提供只读视图。

## 4. Epilogue 回调签名

epilogue 要能组合（反量化 → 激活 → bias → 写回），且不能因为组合而多占寄存器。

待定：函子链还是 `if constexpr` 展开的标签分发。倾向后者，可控性更好。

---

**为什么这四项是关键**：capstone 的两个候选（FP8 MoE grouped GEMM / MLA 风格注意力）
共用 S1 全部零件与 S2 的 10–12 篇，差异只在最后的调度层。这四项对齐了，capstone 选哪个
都拼得起来；不对齐，两个都拼不起来。
